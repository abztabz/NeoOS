# Contributing to NeoOS

NeoOS is governance-first. Contributions must preserve the Founder Charter, Constitution, Core Principles, role boundaries, evidence states, and independent-review requirements.

## Before contributing

1. Read `README.md`.
2. Read `docs/constitution/NEOOS_CONSTITUTION.md`.
3. Read `docs/core-principles/CORE_PRINCIPLES.md`.
4. Read `docs/handbooks/ENGINEERING_HANDBOOK.md`.
5. Search existing issues, GDRs, ADRs, and learning records.

## Workflow

1. Open or select an issue.
2. Complete the Existing Capability Review.
3. Identify the organizational capability being changed.
4. Declare the execution mode.
5. Create a branch.
6. Implement the smallest complete change.
7. Add or update tests and documentation.
8. Open a pull request using the repository template.
9. Do not certify your own work as independently verified.
10. Preserve material dissent in the record.

## Governance changes

A governance change may require a GDR, constitutional or principles amendment, Governance Manual update, charter or SOP update, migration notes, approval evidence, and verification evidence.

Do not modify constitutional or governance text without linking the relevant GDR and authority path.

## Status language

Use evidence-calibrated states: Specified, Assigned, Implemented, Tested, Visually Compared, Independently Verified, Human Approved, Released.

Do not use vague claims such as “done,” “fully implemented,” or “added to NeoOS” without the precise evidence state.

## Contributor terms

By submitting a contribution, you confirm you have the right to submit it and grant the repository owner a perpetual, worldwide, non-exclusive, royalty-free right to use, modify, distribute, sublicense, and commercialize the contribution as part of NeoOS. These terms should receive legal review before broad public contribution.
