# NLR-001 - Project Execution Failure to Governed AI-Native Operating System

**Status:** Canonical organizational learning report  
**Version:** 1.1  
**Date:** 2026-07-14  
**Case study:** Project V8 - Jav's Car House  

## Incident

An approved mobile interface was not converted into a strict, versioned, executable contract. The builder interpreted the design, and the result reached Human Authority before independent verification.

## Root cause

Approved intent remained conversational instead of becoming:

- a binding baseline;
- an executable specification;
- a project contract;
- testable requirements;
- independent verification evidence;
- controlled stage transitions.

## Durable learnings

- approved artifacts are binding baselines;
- autonomy requires explicit boundaries;
- Human Authority is not first-line QA;
- builders cannot self-certify;
- natural language alone may be insufficient;
- Constitution and procedure must remain separate;
- projects improve systems;
- tool selection should be empirical;
- status language must follow evidence;
- working-model adoption and durable enforcement are separate states.

## Founding doctrine

> Projects come and go. Systems remain. Every NeoOS project must follow approved standards and leave the operating system stronger than it found it.
