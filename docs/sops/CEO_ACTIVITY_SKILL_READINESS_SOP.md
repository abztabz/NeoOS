# CEO Activity and Skill Readiness SOP

## Intake and objective

1. Preserve the user's original request verbatim. Identify the desired outcome, deliverable, constraints, authority boundary and whole-objective acceptance criteria. Ask only questions that materially change the plan or outcome, and resolve them before dispatch.
2. CEO decomposes the objective into the smallest independently executable and verifiable activities. Each activity records its inputs, output contract, required skills, tools, dependencies, operational lead, evidence, acceptance tests, stop condition and escalation path. The objective remains the final QA baseline.

## Skill gate before Chief of Staff

3. Match every required skill against the installed and usable catalog. Check actual runtime capability, not only a skill document or installed files.
4. For a missing skill, CEO searches GitHub for candidates, compares fit, provenance, maintenance, license, dependencies, permissions, cost and security. Reuse a proven existing skill first. Pin the selected repository to a full commit SHA and record the source and digest.
5. Inspect instructions and executable content as untrusted third-party material. Install in the appropriate environment, test the activity on a bounded representative input, and record installation path, version, verification evidence and any limitations. A skill document alone does not grant a tool or worker capability.
6. If no suitable skill can be installed and verified within the authorized environment, record the blocker and escalate only the decision required. Do not hand an unready activity to Chief of Staff as executable.

## Workforce and execution

7. CEO hands the complete activity plan and skill readiness record to Chief of Staff. Chief of Staff audits existing agent profiles against skill, tool, authority and availability requirements, then qualifies or provisions only genuine gaps. It returns a readiness report. It does not assign task leads.
8. CEO or operational lead assigns qualified leads. Each lead delegates bounded subtasks to qualified workers, with exact input, output, constraints and acceptance tests. Workers return evidence.
9. A separate QA role checks each result against its activity acceptance criteria and the original objective. PASS advances; FAIL returns to the lead for reassessment and rework; BLOCKED records a concrete blocker and escalation. The producer's own review does not count as independent certification.
10. CEO integrates accepted activities, checks every whole-objective criterion with evidence and delivers the finished output. Capture verified lessons and avoid a new release for each minor patch.

## Runtime limits

The hosted executive bridge may record CEO skill attestations and check the installed marketing bundle against a paired Mac's reported digest. It cannot automatically download and install arbitrary GitHub skills on the Mac. ChatGPT is the active CEO console, and its current review is not independently authenticated QA. Do not claim those capabilities are live until separately implemented and tested.
