# NeoOS Governance Source of Truth

This repository pack converts the current NeoOS working model into a durable, reviewable source-of-truth structure.

## Founding doctrine

> Projects come and go. Systems remain. Every NeoOS project must follow approved standards and leave the operating system stronger than it found it.

## Authority hierarchy

1. Founder Charter
2. Constitution
3. Core Principles
4. Role Charters
5. Governance Manual
6. Role-owned SOPs
7. Project Contracts
8. Execution records and verification evidence
9. Learning records, ADRs, and incident reports

No lower document may contradict a higher document.

## Status discipline

A rule or artifact must use evidence-calibrated status language:

- Proposed
- Adopted in Working Model
- Persisted
- Enforced
- Independently Verified
- Released
- Superseded
- Archived

Conversation approval alone does not equal durable implementation.

## Current package status

This pack is prepared for repository upload. After commit, the documents become **Persisted**.
Runtime or CI enforcement remains incomplete until the controls described in the implementation register are built and independently verified.
